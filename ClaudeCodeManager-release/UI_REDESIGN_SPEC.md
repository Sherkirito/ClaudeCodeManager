# Claude Code Manager：现有功能与 UI 重构交接说明

> 用途：本文件用于交给 Gemini（或其他 UI 重构模型）作为功能不丢失的重构约束。现行版本为 v2.0 preview.4，前端为原生 HTML/CSS/JS 单页应用，后端为 Python 本地 HTTP 服务。
>
> 重构边界：可以完全重写视觉、信息架构和组件结构；**不要删除或改变下述业务能力、数据语义、确认步骤和 API 行为**，除非另行明确决定。

## 1. 产品定位与数据边界

这是一个本地 Claude Code 历史记录管理器，管理 `~/.claude/projects/` 中的 JSONL 会话记录。主要任务是：浏览项目与会话、全文搜索、阅读对话、AI 生成摘要、启动 Claude Code、恢复会话，以及安全地整理/迁移记录。

- 会话、项目、消息检索由本地 SQLite + FTS5 增量索引提供；源数据仍是本地 JSONL。
- 只有用户主动点击 AI 生成时，才把用于摘要的文本发送给已配置的 DeepSeek 或 Anthropic API。
- 删除入口在现行 v2 UI 中是“移到回收站”，会移动原始 JSONL 到应用 `data/trash/` 并留下元数据，不是直接物理删除。
- 项目 ID 是 Claude Code 编码后的目录 ID；不能把它误当成人类可读路径。界面必须同时正确呈现项目真实路径（cwd）。

## 2. 当前信息架构（实际可见）

```text
全局侧边栏
├─ Dashboard（工作台）
├─ Projects（项目）
│  └─ Project detail（项目详情）
│     └─ Session detail（会话详情）
├─ Sessions（跨项目会话）
├─ Settings（设置）
├─ 全局搜索（Enter 后进入搜索结果页）
├─ 快速启动 Claude Code
└─ 关闭管理器
```

当前问题是把全局搜索、返回、快速启动、关闭管理器都塞在侧栏底部；项目详情页又把启动、路径迁移、AI、危险操作全部横向并列在页头，导致层级和风险等级不清楚。

## 4. 核心业务规则（重构必须保留）

### 4.1 启动与恢复 Claude Code

```text
普通打开项目：claude（cwd = 项目路径）
恢复会话：claude --resume <session_id>（cwd 必须优先是会话初始目录/项目根）
```

四种权限必须在所有“打开/恢复”入口保持一致。会话恢复不是只用列表中显示的最新 cwd：后端会重新读取 JSONL，按 `cwd_initial → 项目根 → 前端路径 → 最新 cwd` 依次寻找真实存在的目录。

### 4.2 路径映射与会话迁移不可混为一谈

| 动作 | 作用 | 不做什么 |
|---|---|---|
| 映射新位置 | 记录旧项目路径到新项目路径；之后“打开项目”进入新位置 | 不移动 Claude JSONL，因此不能保证 `--resume` 能在新位置工作。 |
| 迁移会话 | 将 JSONL 放到新路径编码的 Claude 项目目录，并重写 cwd 前缀、备份旧文件 | 不等同于移动真实项目工作区。 |

如果检测到项目已映射但对应会话尚未迁移，恢复必须被后端拒绝（409），前端应展示明确引导，而不是假装启动成功。

### 4.3 安全与确认

- 单项目、单会话、项目批量、会话批量移到回收站均必须二次确认，并准确说明会移动原始记录到 `data/trash/`。
- “迁移会话”必须二次确认，说明会修改 JSONL 的 cwd 并将原始文件备份至 `data/migrations/`。
- “批量总结”必须二次确认，说明会连续调用 AI API；已有摘要会跳过。
- API Key 不得在 UI/API 中回显。

## 6. 现有 UI 的具体问题与重构方向

1. **启动入口分散且重复。** 侧栏、设置、项目页、会话行、会话详情都有“打开”，权限选择也重复出现。建议做一个统一的 `Launch Claude` 操作模型/弹窗：上下文预填“项目”或“会话”，统一选择权限；行内只保留主要启动图标或菜单。
2. **项目详情页头过载。** 当前同时排列打开、映射、迁移、生成简介、批量总结、删除。建议拆为：主操作（打开）；更多菜单（路径管理、AI）；危险区（移到回收站）。
3. **高风险操作缺少独立管理空间。** 已有回收站数据，但没有“回收站”页；路径映射有新增却无删除。建议新增“管理/维护”区域：路径映射、迁移状态、回收站浏览/恢复（若后端补接口）、索引维护。
4. **导航语义混杂。** 全局搜索与返回占侧栏底部，和应用级导航混在一起。建议顶部命令栏放全局搜索，内容区使用面包屑；侧栏仅保留模块和全局工作区/状态。
5. **列表密度失衡。** 会话行同时塞标题、首条消息、项目、日期、cwd 变化、AI 摘要、Token、消息数、权限、打开按钮，扫描成本高。建议区分紧凑列表与详情抽屉/预览；AI 摘要可作为可展开预览。
6. **中英文与图标不一致。** 菜单用英文、正文用中文，导航图标是字母 D/P/S/G。建议确定中文产品语言，使用统一线性图标系统与清晰标签。
7. **状态反馈较弱。** 目前是短暂 toast 和浏览器 `confirm`。建议使用可读的进度、错误状态、可取消/完成摘要；批量 AI 操作至少显示已处理/跳过/失败数量。
8. **设置职责不完整。** API 配置、快速启动、索引维护和关闭应用混在两张卡中；默认路径保存逻辑有缺口。建议分为 AI 服务、默认工作区与权限、数据索引、应用危险操作。

2. 所有大列表、会话消息必须继续使用后端分页，不得全量拉取 JSONL。
3. 所有 AI 功能、打开/恢复功能、删除/迁移风险提示均要有加载、成功、失败状态。
4. 继续使用“移到回收站”接口，不调用旧版硬删除 API。
5. 会话恢复一定传 `project_id` + `session_id` + `resume: true`，使后端能执行正确 cwd 解析和迁移拦截。
6. 支持四种权限模式，并在任何启动路径保持同一含义。
7. 不能让 API Key 回显到页面或日志。
8. 保留原生 Windows 目录选择调用，不用浏览器文件上传来替代。

## 9. 已知现状缺口（重构可以顺带修复，需后端配合的要标注）

- UI 没有回收站浏览、恢复或彻底删除，后端目前也没有恢复 API。
- UI 无法删除路径映射，虽然有 `/api/v2/path-map-delete`。
- UI 没有“全项目生成简介”入口，虽有 `/api/describe-all`。
- UI 未显示 `claude` 命令是否可用，虽有 `/api/claude-status`。
- 设置页默认路径与权限并非通过“保存配置”持久化；建议修复前端和/或扩展后端 `/api/set-api-config`。
- Provider 切换后模型下拉不会在页面中实时更新，需刷新设置页后才反映后端重置结果。
- 当前使用内联 `onclick` 和 `innerHTML` 拼接；建议重构为事件委托/组件渲染，并继续严格转义来自 JSONL 的内容。
